# App layout design audit

Scope: `/create`, `/projects`, `/servers/discover`, `/servers/$serverId`, `/profile`,
`/appearance/*`, `/healthcheck`, and the room loading/error states under `AppLayout`.
Sidebar components and interactions are excluded. This is a source review, not a browser or
screenshot review. General layout findings remain recommendations. Noir is implemented, and the
Color studio follow-up below records the subsequent `/appearance/colors` fixes.

## Suggested order

1. Clarify the shared route heading and simplify `/create` around its required input.
2. Correct error states, mislabeled navigation, and creation validation feedback.
3. Align page gutters/type scales; remove manual blur and redundant card nesting.
4. Check long content, keyboard focus, and small screens after those changes.

## Implemented in this pass

- `Noir / OLED` is available wherever presets are listed: Settings, Theme Studio, and previews.
- Dark uses a black canvas, graphite cards, soft white text, and silver actions. Light uses neutral
  paper surfaces. Semantic error/success/warning colors remain recognizable.
- The solid shell uses the canvas color for Noir, keeping cards visually separate. Neutral theme
  backgrounds keep neutral shader endpoints instead of acquiring a blue cast.
- Existing account saving and custom overrides are preserved. Selecting Noir does not change
  the chosen mode, glass material, motion, or background. Use Dark + Solid for the black canvas.
- The palette has targeted text, input-boundary, and focus-ring contrast checks, including the
  shared focus ring's 50% alpha, plus persistence and live token application coverage.
